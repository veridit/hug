## Goal
Where you are focused, in a list or a task's page, the > blinks like a cursor; while you type, only the text cursor blinks.

## Purpose
An underlined > reads as a key you can press; a pulsing one reads as where you are.

## Principle
One mark for 'you are here', moving like a cursor; only one thing moves at a time.

## Relevant details
General rule (Jørgen 2026-11-20 12:10Z on bxcsmk): wherever you can type, a blinking underscore; wherever you are just positioned, a blinking >. Never both at once. bxcsmk was the same request filed again (dropped as a duplicate; its screenshot is attached here).

Rule (Jørgen 2026-11-20 11:49Z on 911j70): 'it is blinking like a cursor would, but it isn't for entry. That's where your current position is ... either you have started entering and that one is blinking, or you are just focused somewhere, and then the greater than ... if it's also selected, is blinking.' So: one blinking thing on screen. In lists (911j70's > before the current cell, rxr4z8's ⋗ on a marked row) and in a task's page, the focus sign blinks; when a text box or prompt is open, its text cursor blinks and the focus sign is still.

Change (Jørgen 2026-11-20 10:33Z, request 1, screenshot screen-1132.ans): today the focused row's > is drawn in theme.cursor, underlined and static (since v0.7.66). An underlined character reads as a key you can press (the view line underlines keys), and > is a key: in a page it goes to the bottom (tui.go scroll: '>', 'end' -> GotoBottom; '<' -> GotoTop). So the > loses the underline and pulses or blinks in the accent at the box cursor's 530 ms instead, as a cursor does. When the answer box is open, its cursor is the one that moves and the > stays still, so only one thing moves at a time (qpp30y). Same rule as 911j70: the current cell gets >, no underline. His words: 'the cursor underlines the greater than that looks like I can utilize a shortcut ... I think there has to be the greater than pulsating like it is a cursor, which brings me to focus there.' He also expects > and < to go to the bottom and top in this view; check that they do.

Split from kg07bt (shipped v0.7.66, accepted by Jørgen 2026-11-20 10:33Z: 'this ticket is accepted and my feedback ... can be new tickets').
