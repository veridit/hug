## Goal
Jørgen confirms v0.7.96 installed: a board lock is free the moment it is released, so no pass looks busy after it ended.

## Purpose
A released lock stayed held for milliseconds while git started elsewhere; it flaked CI and could make the TUI or MCP see a finished sync as running.

## Principle
One confirmation per shipped change; nothing here changes what he sees.

## Relevant details
Shipped: 3qa9bt (389544a7, CI 44912084495 attempts 1 and 2, 8/8 each). Cause: internal/flock released a lock by closing the file; a fork in another goroutine copies open files into git's child until it execs, so the lock stayed held. Fix: unlock, then close. Stress on origin/main with a git-forking neighbour: 7/150 failures (3/150 with -race); with the fix 150/150 and 500/500. New test TestReleaseFreesLockACopiedDescriptorShares catches the old release.
