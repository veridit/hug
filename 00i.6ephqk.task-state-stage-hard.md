## Goal
Every task file says state (todo, doing, done, dropped) and stage within it (todo: draft, design, depends, ready, review; doing: active, waiting, depends, review). The tree is hard-coded in one place (huginn/internal/task/states.go), printed by hug task states, and every node declares its own fields named after it (doing_since, waiting_on, waiting_since, design_question, review_by, dropped_reason, done_at, done_release). The state picks the main display (section, color, order); the stage fine-tunes it (the second line, the marker, what the detail view shows first). Full design: tmp/lanes/805p6y-states.md.

## Purpose
Jørgen 2026-11-17 10:03-10:14: half of the in-progress tasks were really waiting on something outside the agent (CI, a release, a reply) and the board could not say so; he wants to see what each task is doing right now, with the view tailored to it. He ruled the tree, the field naming, depends and review under both todo and doing, and the TUI take for review.

## Principle
Hard-coded because every node has semantics hug acts on; a configurable tree would need this one underneath anyway. Declarative and easy to check: one table, lint holds every file to it. What hug can derive (draft, depends, ready, the active check) is written by hug or read live, never by hand. A node's fields exist only while the task is in it; leaving moves them to History. No backward compatibility: hug upgrade migrates status to state and stage. Subtle display.

## Relevant details
Supersedes 805p6y (dropped: it described a now-line on checks). Builds on zhvkmj (colors per state) and 102bc0 (one-line rows). Commands: take (todo/* -> doing/active, todo/review -> doing/review with review_by), wait ID "on what", resume ID, design ID "question", done, drop ID "reason"; MCP task_update actions wait, resume, design. Sections: NEXT UP (todo ready/design/draft/review), DEPENDS (todo/depends), IN PROGRESS (doing/*), RECENTLY DONE. 16dxsr later lets a waiting_on condition end itself.
