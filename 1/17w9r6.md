## Goal
The sort and filter pickers share one interaction: j/k move a highlight, Enter picks, a field's letter picks it at once.

## Purpose
Jørgen 2026-11-19 11:41Z (crab console): filter and order behave differently and he prefers filter's; the sort picker (s) takes only letters, no j/k to move and select. Code read 11:42Z: filters.go updateFilter has j/k/up/down/ctrl+n/p and Enter on a highlighted field; sort.go updateSort has letters, r, c, backspace and Enter only, no highlight.

## Principle
One picker behaviour, taken from the filter picker; the sort picker keeps its own meaning (a letter adds a field, again flips it, Enter applies) on top. No new keys beyond what filter already uses. Calm rules (qh9ep1 check 9): the highlight is the same cue in both.

## Relevant details
Sort: a highlighted row in the field list (sortText), j/k/up/down/ctrl+n/p move it, Space or Enter on the highlight adds or flips that field as its letter would, Enter with nothing new applies the draft (as today). Filter: unchanged unless the shared code needs it. Code: huginn/internal/tui/sort.go (updateSort, sortText), filters.go (updateFilter, filterText). Help goldens list the same keys for both. Jørgen's 'press A and space, which expands the thing that starts with A' is asked on this task to pin which picker and behaviour he means.
