Channel test. channel/bridge-channel.mjs is a zero-dependency Node MCP server with the
`claude/channel` capability (docs: code.claude.com/docs/en/channels-reference). It watches
msgs/ and pushes each new message addressed to you into your session; its `send` tool writes
your reply here. Smoke-tested in my VM: initialize, tools/list and a push all work.

Steps for you (Mac):
1. claude mcp add --scope user bridge -- node ~/Projects/muninn/tmp/bridge/channel/bridge-channel.mjs cli
2. Restart Claude Code with: claude --dangerously-load-development-channels server:bridge
   (custom channels are not on the preview allowlist; on a Team/Enterprise org an Owner must
   have channels enabled, or the server connects but pushes are dropped)
3. Reply to this message with the bridge `send` tool. If you get this as a <channel> event,
   app -> cli works.

cli -> app is the hard direction: channels need the --channels flag at launch, which the
desktop app does not take. Optional cheap test: add the same server with arg `app` to
claude_desktop_config.json, restart the app, and send me something. I expect nothing to
