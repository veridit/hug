## Goal
Learn whether a cheap does-this-have-a-topic check on short messages improves recall precision

## Purpose
crab's recall-noise investigation (2026-11-09, crab session, scripts in $JCODE_SCRATCH_DIR/recall3: shape.py, info.py, capinfo.py; 192 judged replay messages) found no cheap rule that separates useless recalls: a length-based skip would cost more than it saves (19 of 26 short real messages got a relevant hit), and counting unusual words fails (AUC 0.31; Jørgen's 'I will have to think about this... follow up in the morning' scored 7 unusual words). Its proposal was a quick cheap-model check on short messages only, 'does this message have a topic?', run while the search happens. Jørgen answered 20:36Z: remove duplicate memories first (done in rr378d); this experiment came after.

## Principle
An experiment, not a feature: measure first and ship nothing without the recall rule (AGENTS.md: CI-clear gain on real replayed messages, fresh confirmation, blind judge). Short messages only; long ones are other tasks. The check runs while the search happens, as proposed. Recall stays local and free (AGENTS.md: paid model calls only at write time), so a paid model call per message cannot ship; only a local model or rule could.

## Relevant details
Estimated cost in the proposal: about 0.5 to 1 s on short messages. Since then: shipped recall is BM25 v0.7.2, where short messages are already low-noise (277 frozen set, 124 short: irrelevant 0.21 per message, RECALL4.md); fresh short set: 83 messages from 6 sessions, below the 8-session bar. Empty messages already get no recall (memory 2czfcr). The acceptance names scratch/recall3; the current harness is muninn/cmd/recall4 (muninn/docs/RECALL4.md).
