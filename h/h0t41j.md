## Goal
A local web UI for browsing and fixing memories

## Purpose
Jørgen chose Go for muninn partly to ship one binary with MCP, a web UI and a TUI (memories 2rarx4, mkggrq), and decided TUI now, web UI later for both tools (huginn/DESIGN.md D5; szd026). The reason for a web UI: it runs locally so it can be opened from vendor apps (Claude, ChatGPT/Codex) to view and edit memories and tasks (muninn/docs/ROADMAP.md 'Web UI from vendor apps').

## Principle
Local only: the server binds to loopback, nothing hosted (that is j0xa38). The same views and actions as the TUI through the same scoped binding, not a second design. TUI first, web UI after (D5).

## Relevant details
A first web UI already exists: 'hug mem serve' runs the watcher and a loopback web UI (muninn/internal/web/web.go, 293 lines; static/index.html, 154 lines) with a JSON API for search, related, recall, places, remember, forget, injections, stats and embed. It does not show the TUI's views, and tasks have no web UI ('hug task serve' does not exist). Acceptance names 'muninn serve'; the command is now 'hug mem serve'. Epic gem59b (Launch).
