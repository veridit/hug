## Goal
hug mem commands work on a machine with no ~/.jcode directory instead of panicking.

## Purpose
Found by mizaru 2026-11-18 while testing mbdfzs with a scratch home directory: every hug mem command panicked 'slice bounds out of range [1:0]' in harness.DiscoverJcode, because the global instance is only added when ~/.jcode exists and the sort then slices out[1:] of an empty list. A person without jcode (Claude Code or Codex only) hits it on first use.

## Principle
Fix the sort guard only; no other change to instance discovery.

## Relevant details
muninn/internal/harness/jcode_instances.go:124 sort.SliceStable(out[1:], ...) when len(out)==0. Repro: run hug mem remember with a home directory that has no .jcode (scratch store).
