## Goal
An agent working on two tasks at once, because they ship in the same change or release, holds both in doing: 'hug task take B --with A' is allowed while A is active, both show in IN PROGRESS together ('with A'), and each closes on its own. hug guides the agent there: the busy refusal offers it as a fix, and ticking a check on a task you do not hold says to take it with the one you're on.

## Purpose
Jørgen 2026-11-18 20:37Z with a screenshot of sql_saga's board: sabertooth worked dee3fq and bqtzce together for one release, but take refused a second doing, so bqtzce sat in NEXT UP as 'ready' with 2/2 checks ticked. 'Obviously, I think both should have been in progress. How can we allow this and help guide the agents.'

## Principle
Doing still means on it now (n2hq8p): one active task, plus those taken explicitly with it. The link is stated, never guessed, and stays visible. A task you only read or plan is not taken with. People (model human) follow the same rule.

## Relevant details
busy.go: busy() refuses the second take with BusyFixes + DetourFix (4tycwd). Add a fifth fix, take B with A, saying when to use it (they ship together). Store: a with=A field on B; IN PROGRESS marks 'with A'. Ticking a check on a todo task you don't hold ticks silently today (sql_saga bqtzce: 2 ticks at 20:24 while todo); reply with a fix line to take it with the active one. MCP task_take gets 'with'. Help and the AGENTS.md task section say it in one line.
