## Goal
A memory an agent saves over MCP lands in the caller's project, and the reply says plainly where it landed.

## Purpose
2026-11-28 syncthing agent (report ~/Projects/syncthing/tmp/hug-mcp-scope-report.md): one hug mcp per jcode server serves sessions from many directories; its 'here' is the server's cwd (lodgebook), so syncthing memories were filed under lodgebook. A write also answered 'Error: no visible memory' after it was stored, so the agent wrote a duplicate.

## Principle
Only the per-session hook may trust its own cwd. The MCP path needs the caller's directory (as task_take needs cwd) or an explicit global choice; a directory goes through hug's project lookup, never a hand-written folder: scope. A write that is stored never answers with an error.

## Details
Code: mcpserver/mcp.go:124-128 Bind uses os.Getwd() once at server start; memory_remember (mcp.go:186-199) carries no directory. binding.go:772-783 RememberPlaced writes (ingest.RememberWith), reindexes, then b.Resolve(m.ID); Resolve (binding.go:298-308) returns 'no visible memory' when the new memory's scope is outside the server's binding, after the write.
